## fizz ship

<include>../generated/commands/ship.md</include>

A Ship checks every Machine, plans its Steps, asks any Questions, then applies the plans in parallel. The Ledger lists what changes on each Machine by address: `vp:node`, `repos:t3code`.

### Answering in advance

`--answer kind=choice` answers every Question of a kind: `range=bump|skip|downgrade`, `config=overwrite|stop`, or `mode=managed|skip`. `--answer kind:subject=choice` answers one, such as `range:vp:vercel=bump`, and wins over the kind's answer.

Without a terminal, a Question is never waited on: the answer is skip. Piped to a file, the Ledger prints the full list once at the end.

### A different config elsewhere

If another Machine's config was edited there, was never written by a Ship, or was shipped there more recently than this one last reached it, the Ship asks first: use that config here and ship it, overwrite it with this one, or stop. `--overwrite-config` answers overwrite in advance, and without a terminal the Ship stops instead.

## fizz logs

<include>../generated/commands/logs.md</include>

Every Ship, dry runs included, writes a Ship Log on the Machine that started it, under `~/.local/state/fleetfizz/logs`, and ends by printing its id: `log: fizz logs 2026-10-18T14-03-22Z-connors-macbook-pro`. Each line has its time, its level, and the Machine and phase it belongs to; lines a Machine printed start with `> `. A Machine keeps its last 20.
