The config lives at `~/.config/fleetfizz/config.jsonc`, the same path on every Machine. The copy on the Machine you ship from is the one a Ship reads, and the Ship copies it (and `schema.json`, for editor validation) to every other Machine.

```jsonc title="config.jsonc"
{
  "$schema": "./schema.json",
  "machines": ["connors-mac-studio", "connors-macbook-pro"],
  "repos": {
    "cloneRoot": [
      { "machines": ["connors-mac-studio"], "path": "/Volumes/StudioStack SSD/fleetfizz/clones" },
    ],
    "items": {
      "t3code": {
        "origin": "connorch/t3code",
        "ref": "main",
        "platforms": ["darwin"],
        "install": "pnpm install && pnpm build",
        "outputs": ["~/Applications/T3 Code.app"],
      },
    },
  },
  "vp": {
    "version": "1.1.0",
    "node": "24.18.1",
    "pnpm": "^10",
    "items": {
      "vercel": "^59.25.4",
      "wrangler": { "range": "^4.136.3", "machines": ["connors-mac-studio"] },
    },
  },
  "brew": {
    "items": {
      "gh": "*",
      "oven-sh/bun/bun": "latest",
      "tmux": { "range": "*", "platforms": ["linux"] },
    },
  },
  "cask": { "items": { "ghostty": "latest" } },
  "files": {
    "items": {
      "wovn": "~/.config/wovn",
      "karabiner": { "path": "~/.config/karabiner", "exclude": ["automatic_backups"] },
    },
  },
}
```

## vp

<include>../generated/config/vp.md</include>

A Ship installs the newest version in a Global's Range when it is missing or below the Range, and leaves it alone anywhere inside it. `latest` always installs the newest version, and `*` installs only when missing. A Global not in the config is never uninstalled.

A Global above its Range usually means someone updated it by hand, so the Ship asks before changing anything: bump the Range, skip it on that Machine, or downgrade into the Range.

Node and the package-manager defaults only take effect in vp's managed mode, where `node`, `npm`, `pnpm`, `yarn`, and `bun` run vp's version instead of a system install such as Homebrew's Node. A Machine with any tool in system-first mode gets a Question: switch it to managed mode (`vp env on`), or skip, which leaves the mode alone and skips that Machine's Node and package-manager defaults. Skip is the default, since switching changes which `node` every shell there runs.

Repos run last, after Shared Files, vp, and the Homebrew packages, so an Install Command can read a Shared File or use a Formula from the same Ship; when vp, Node, or a Global fails on a Machine, that Machine's repo changes are skipped ("depends on vp").

## cask

<include>../generated/config/cask.md</include>

`brew` and `cask` need Homebrew on the Machine; a Ship never installs it, and `brew:brew` fails on a Machine without it. Homebrew installs only a package's newest version, so a Range there is only `"*"` (install when missing) or `"latest"` (run `brew update`, then upgrade on every Ship). A `"latest"` package always shows as planned in a dry run; whether there is something newer is known only after `brew update`, and the Ledger then shows the version it reached.

## files

<include>../generated/config/files.md</include>

A Ship reads each Shared File on the Machine it runs from and copies it, with its mode bits, to every targeted Machine. A directory is mirrored: what the Starting Machine no longer has is deleted there too, except excluded paths. A symlink is copied as a link. An Item the Starting Machine does not have is skipped everywhere, and one over 10 MB fails.

Each Machine keeps a record of the last copy a Ship wrote there. Before overwriting, a Ship asks (`--answer file=overwrite` or `skip`; skip is the default) when the copy there was edited since, when no Ship wrote it, or when it came from a newer Ship that missed the Starting Machine. Contents travel only on the ssh session's stdin, so they never appear in a script, the Ledger, or the Ship Log.

## Targeting

Every section, each Item in its `items`, and each Variant take two optional fields that narrow where they apply. They combine with AND, so an Item applies where both it and its section do, and an unset field means every one.

## Variants

When one Item needs a different definition on some Machines, write it as a list of Variants: whole entries, each with its own Targeting. A Machine gets the first Variant that targets it, and an Item with no Variant for a Machine is not targeted there. A bare value with no Targeting, last, covers every other Machine.

```jsonc title="config.jsonc"
{
  "machines": ["connors-mac-studio", "bluefin"],
  "vp": {
    "items": {
      "vercel": [{ "platforms": ["linux"], "range": "^60.0.0" }, "^59.25.4"],
    },
  },
}
```

`repos.cloneRoot` takes Variants the same way: a path, or a list of `{ path, platforms?, machines? }`.
