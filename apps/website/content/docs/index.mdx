## Why

Agents don't stop when you close your laptop, so your dev setup now lives on more than one machine: a desktop that runs agents all night, a laptop you take with you, maybe a Linux box. Each one needs the same Node, the same CLIs, and the same repos at the same commit, and by hand they drift.

fleetfizz keeps them in line. One config lists your Machines and what each one needs. One command, `fizz ship`, brings every Machine up to it.

## What it keeps in line

- **Globals**: the global packages of vp, npm, bun, and pnpm, at semver Ranges. Which package managers and Node you use stays yours.
- **Tracked Repos**: a Managed Clone of each repo, reset to its origin ref and installed with its own Install Command.
- **Formulae and Casks**: Homebrew packages and macOS apps.
- **Skills**: agent skills, installed with the skills CLI and kept at their GitHub ref.
- **Shared Files**: files and directories copied from the Starting Machine, such as dotfiles or app configs, with an optional command to run after each copy.

Every entry can target some Platforms or Machines and skip the rest. [Config](/docs/config) covers every field.

## How a Ship works

You run `fizz ship` on any Machine in the Fleet, the Starting Machine. It reaches the others over Tailscale SSH and runs in four steps:

1. **Check.** Read each Machine's current state. Nothing changes.
2. **Plan.** Compare that state to the config and list the Steps each Machine needs.
3. **Questions.** Ask about anything the Plan cannot decide alone, such as a Global that someone upgraded above its Range. No Machine changes until every Question is answered.
4. **Apply.** Run every Machine's Steps in parallel.

The Ledger shows the result: one line per Machine and, under it, each Item that changed. `fizz ship --dry-run` stops after the Plan, and `fizz report` prints the last Ledger of a Ship from this Machine again.

The config names one fleetfizz `version`. Every fizz switches to it before it reads the config, and every Ship copies the config and installs that version on every Machine, so any Machine can run the next one.

## What it does not do

- **Run anything in the background.** There is no agent, daemon, or server. A remote Machine needs only Tailscale SSH, `git`, and a shell, plus the package managers its config uses and Node 24 with one to install fizz.
- **Uninstall.** Removing an Item from the config leaves it installed.
- **Fail on an offline Machine.** It is skipped and catches up on the next Ship.
- **Keep your GitHub token.** The Starting Machine lends it to each Machine for one Ship, on stdin, so private repos clone. It is never written to disk.

[Getting started](/docs/getting-started) installs fleetfizz and runs a first Ship.
