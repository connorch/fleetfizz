---
title: Getting started
description: Set up Tailscale SSH, run fizz init, and run your first Ship.
---

This guide takes two or more macOS or Linux Machines to a first Ship. Pick one Machine to ship from; the first Ship sets up fleetfizz on the others.

Every Machine needs `git` and `curl`. macOS has both; on Linux, install them with your package manager if they are missing.

## 1. Turn on Tailscale SSH everywhere

fleetfizz reaches every Machine with `tailscale ssh`, so every Machine must be on the same tailnet with Tailscale SSH on.

On a Mac, use the open-source `tailscaled` from [Homebrew](https://brew.sh). The Tailscale app can connect to other Machines but cannot accept Tailscale SSH, so quit and remove it first if you have it.

```sh
brew install --formula tailscale
sudo brew services start tailscale
sudo tailscale up
sudo tailscale set --ssh
```

On Linux:

```sh
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
sudo tailscale set --ssh
```

If a Machine is already on your tailnet, skip `tailscale up` and run only `sudo tailscale set --ssh`.

Then, in the Tailscale admin console under **Access controls**, let your own user in with `accept` instead of `check`. With `check`, Tailscale asks you to sign in in a browser, and a Ship waits on that prompt. fleetfizz never logs in as root, so root can stay behind `check`:

```json
"ssh": [
  {
    "action": "accept",
    "src": ["autogroup:member"],
    "dst": ["autogroup:self"],
    "users": ["autogroup:nonroot"]
  },
  {
    "action": "check",
    "src": ["autogroup:member"],
    "dst": ["autogroup:self"],
    "users": ["root"]
  }
]
```

From the Machine you will ship from, check each other Machine. It should print `ok` with no prompt:

```sh
tailscale ssh connors-macbook-pro echo ok
```

## 2. Install fleetfizz

On the Machine you will ship from, install vp, then open a new terminal so `vp` is on your `PATH`, and install fleetfizz with it. The first Ship installs vp and fleetfizz on the other Machines.

```sh
curl -fsSL https://vite.plus | bash
vp install -g fleetfizz
```

## 3. Run fizz init

```sh
fizz init
```

`fizz init` first checks this Machine: vp, Tailscale connected with Tailscale SSH on, and, for Items that need them, Homebrew and a logged-in `gh`. It changes nothing there; for each problem it prints the command that fixes it. Fix any that are required and run it again.

Then it asks:

- **Which Machines are in the Fleet**, from your tailnet. This Machine is always one. A Machine that is offline or has no Tailscale SSH yet can still be picked; a Ship skips it until it can reach it.
- **Whether to pin vp and Node** to the versions on this Machine.
- **Which Globals, Formulae, and Casks to keep in line**, from what this Machine has installed.
- **Which Shared Files to copy**, from common dotfiles like `~/.gitconfig` and `~/.zshrc` that exist here.

It writes `~/.config/fleetfizz/config.jsonc` with `schema.json` beside it, so your editor checks the config as you edit it, and shows what each Machine gets. Add more at any time:

```sh
fizz config add repos connorch/t3code --install "pnpm install && pnpm build"
fizz config add brew tmux --platform linux
fizz config add files ~/.config/ghostty
```

[Config](/docs/config) covers every field, if you would rather write it by hand.

If your config's `brew` section targets a Linux Machine, install Homebrew there too. A Ship never installs Homebrew itself.

If a Machine already has a config, `fizz init` shows it instead. A new Machine joins an existing Fleet from a Machine that has the config: `fizz config add machines`, then ship.

## 4. Ship

See where each Machine stands, without changing anything:

```sh
fizz status
```

Then ship:

```sh
fizz ship
```

The Ledger lists each Machine and what changes there, and updates as the Ship runs. Press `f` to see every Item, unchanged ones included. If the Ship asks a Question, such as whether to switch a Machine's vp to managed mode, answer it before anything changes. Any Tracked Repo that is private needs `gh` logged in here: the Ship lends its token to each Machine for that Ship only.

After the first Ship, every Machine it reached has fleetfizz and the config, so you can ship from any of them. An offline Machine is skipped and catches up on a later Ship.
