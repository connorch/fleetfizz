---
title: Getting started
description: Install fleetfizz, run fizz init, ready your other Machines, and run your first Ship.
---

This guide takes two or more macOS or Linux Machines to a first Ship. Pick one Machine to ship from; the first Ship sets up fleetfizz on the others.

## 1. Run fizz init

On the Machine you will ship from, with Node 24 or newer, install fleetfizz with any package manager and run `fizz init`:

```sh
npm install -g fleetfizz   # or: pnpm add -g, bun add -g, vp install -g
fizz init
```

`fizz init` first checks that this Machine can ship: Tailscale connected, with Tailscale SSH on. For each problem it prints the command that fixes it; run them, then run `fizz init` again. On a Mac, Tailscale SSH needs the open-source `tailscaled` from Homebrew: the Tailscale app cannot accept it, so quit and remove the app if you have it.

Then it asks which Machines on your tailnet are in the Fleet, what to keep in line from this Machine (Globals, Formulae, Casks, skills, and dotfiles), and whether to add the fleetfizz skill, which teaches your coding agent to edit the config and ship. It writes the config to `~/.config/fleetfizz/config.jsonc` and offers a dry run.

Add more at any time with `fizz config add`, or edit the config by hand; [Config](/docs/config) covers every field.

```sh
fizz config add repos connorch/t3code --install "pnpm install && pnpm build"
fizz config add files ~/.config/ghostty
```

## 2. Ready the other Machines

Each other Machine needs `git`, Node 24, and the package manager that installed fizz here, so the first Ship can install fleetfizz there. A Ship never installs Node, a package manager, or Homebrew; if the config's `brew` section targets a Linux Machine, install Homebrew there too.

Each one also needs to be on your tailnet with Tailscale SSH on. `fizz init` marks any that have it off. On a Mac:

```sh
brew install --formula tailscale
sudo brew services start tailscale
sudo tailscale up
sudo tailscale set --ssh
```

On Linux:

```sh
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
sudo tailscale set --ssh
```

Then, in the Tailscale admin console under **Access controls**, let your own user in with `accept` instead of `check`. With `check`, Tailscale can ask you to sign in in a browser, and a Ship's Check of that Machine waits on that prompt until it gives up after two minutes. fleetfizz never logs in as root, so root can stay behind `check`:

```json
"ssh": [
  {
    "action": "accept",
    "src": ["autogroup:member"],
    "dst": ["autogroup:self"],
    "users": ["autogroup:nonroot"]
  },
  {
    "action": "check",
    "src": ["autogroup:member"],
    "dst": ["autogroup:self"],
    "users": ["root"]
  }
]
```

From the Machine you ship from, check each other Machine. It should print `ok` with no prompt:

```sh
tailscale ssh connors-macbook-pro echo ok
```

## 3. Ship

```sh
fizz ship
```

The Ledger lists each Machine and what changes there, and updates as the Ship runs. Press `f` to see every Item, unchanged ones included. If the Ship asks a Question, such as whether to bump a Range a Machine has outgrown, answer it before anything changes. A private Tracked Repo needs `gh` logged in here: the Ship lends its token to each Machine for that Ship only. The Ship ends by printing its id, and `fizz logs <ship-id>` shows everything it did.

When a Machine lacks a tool the config installs in another section, such as pnpm as an npm Global or the skills CLI as a pnpm Global, the first Ship installs it and skips what needs it ("ship again"). Run `fizz ship` again to install the rest.

After the first Ship, every Machine it reached has fleetfizz and the config, so you can ship from any of them, or ask your agent to. An offline Machine is skipped and catches up on a later Ship. A new Machine joins with `fizz config add machines`, then a Ship.
