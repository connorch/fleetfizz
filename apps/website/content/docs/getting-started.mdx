---
title: Getting started
description: Set up Tailscale SSH, install fleetfizz, and run your first Ship.
---

This guide takes two or more macOS or Linux Machines to a first Ship. Pick one Machine to ship from; the first Ship sets up fleetfizz on the others.

Every Machine needs `git` and `curl`. macOS has both; on Linux, install them with your package manager if they are missing.

## 1. Turn on Tailscale SSH everywhere

fleetfizz reaches every Machine with `tailscale ssh`, so every Machine must be on the same tailnet with Tailscale SSH on.

On a Mac, use the open-source `tailscaled` from [Homebrew](https://brew.sh). The Tailscale app can connect to other Machines but cannot accept Tailscale SSH, so quit and remove it first if you have it.

```sh
brew install --formula tailscale
sudo brew services start tailscale
sudo tailscale up
sudo tailscale set --ssh
```

On Linux:

```sh
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
sudo tailscale set --ssh
```

If a Machine is already on your tailnet, skip `tailscale up` and run only `sudo tailscale set --ssh`.

Then, in the Tailscale admin console under **Access controls**, let your own user in with `accept` instead of `check`. With `check`, Tailscale asks you to sign in in a browser, and a Ship waits on that prompt. fleetfizz never logs in as root, so root can stay behind `check`:

```json
"ssh": [
  {
    "action": "accept",
    "src": ["autogroup:member"],
    "dst": ["autogroup:self"],
    "users": ["autogroup:nonroot"]
  },
  {
    "action": "check",
    "src": ["autogroup:member"],
    "dst": ["autogroup:self"],
    "users": ["root"]
  }
]
```

From the Machine you will ship from, check each other Machine. It should print `ok` with no prompt:

```sh
tailscale ssh connors-macbook-pro echo ok
```

## 2. Install what fleetfizz needs

If your config will list Homebrew packages (`brew` or `cask`) for a Linux Machine, install Homebrew there too. A Ship never installs Homebrew itself.

The Machine you ship from also needs:

- **vp**, to install fleetfizz: `curl -fsSL https://vite.plus | bash`, then open a new terminal so `vp` is on your `PATH`. The first Ship installs vp on the other Machines.
- **gh**, logged in with `gh auth login`, if any Tracked Repo is private. The Ship lends its token to each Machine for that Ship only, so the repo can clone. Without it, private repos fail and everything else still ships.

## 3. Install fleetfizz

On the Machine you will ship from:

```sh
vp install -g fleetfizz
```

## 4. Write the config

Find each Machine's name with `tailscale status`. A Machine is named by the first part of its tailnet name, so `connors-macbook-pro.tail1234.ts.net` is `connors-macbook-pro`.

Create the config directory:

```sh
mkdir -p ~/.config/fleetfizz
```

Then write `~/.config/fleetfizz/config.jsonc` (or `$XDG_CONFIG_HOME/fleetfizz/config.jsonc` if you set `XDG_CONFIG_HOME`) and list every Machine, the one you ship from included:

```jsonc title="config.jsonc"
{
  "$schema": "./schema.json",
  "machines": ["connors-mac-studio", "connors-macbook-pro"],
  "vp": {
    "version": "1.1.0",
    "node": "24.18.1",
    "items": { "vercel": "^59.25.4" },
  },
}
```

This keeps vp, Node, and the `vercel` CLI in line. [Config](/docs/config) covers Tracked Repos, Homebrew, and every other field.

## 5. Ship

See what would change, without changing anything:

```sh
fizz ship --dry-run
```

Then ship:

```sh
fizz ship
```

The Ledger lists each Machine and what changes there, and updates as the Ship runs. Press `f` to see every Item, unchanged ones included. If the Ship asks a Question, such as whether to switch a Machine's vp to managed mode, answer it before anything changes.

After the first Ship, every Machine it reached has fleetfizz and the config, so you can ship from any of them. An offline Machine is skipped and catches up on a later Ship. To add a Machine later, turn on Tailscale SSH there and add it to `machines`.
